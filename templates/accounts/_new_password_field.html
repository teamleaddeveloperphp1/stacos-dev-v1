{% load crispy_forms_field i18n %} {% comment %} The password field for a password being *chosen*: the same control as `_password_field.html`, plus the two things that field was missing. A strength meter, because "at least 10 characters" is a floor, not advice, and a floor on its own teaches people to type exactly ten characters. And the rule list, checked live, because the alternative is discovering on submit that the password is too short — after the browser has cleared both password boxes, which is the moment people give up and reuse something. The rules shown here are only the ones a browser can honestly check. Two more are enforced server-side and deliberately not claimed here: whether the password is on the common-password list, and whether it is too close to the name and email in the fields above. Promising a check the page cannot perform is worse than not mentioning it — see `RegistrationForm.clean`, which runs Django's configured validators and is the only verdict that counts. {% endcomment %}
