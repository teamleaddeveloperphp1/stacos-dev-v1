{% translate "Security and privacy" %}

{% blocktranslate %} STACOS holds tax identifiers, filings, statutory registers and board minutes. This page describes how that data is separated, protected and accounted for. {% endblocktranslate %}

{% blocktranslate %} Everything below describes the system as it is deployed today. Where we have no certification, we say so rather than implying one. {% endblocktranslate %}

{% translate "Tenant isolation" %}

{% blocktranslate %} Every customer-owned record carries the identifier of the account that owns it. The application's default database manager refuses to run a query that has not been scoped to an account — an unscoped query raises an error rather than returning data. PostgreSQL row-level security enforces the same boundary independently at the database, using a role that cannot bypass it. A dedicated test suite attempts cross-account reads and writes against every model on every build and fails the build if any of them succeeds. {% endblocktranslate %}

{% translate "Access between organisations" %}

{% blocktranslate %} A professional firm can only see a client's records through an engagement: a record the client approves, scoped to named entities and named compliance categories, with a start date and an end date. There is no other route. Ending an engagement removes access on the same request — not on a nightly job — and the organisation keeps everything. {% endblocktranslate %}

{% translate "Authentication" %}

{% blocktranslate %} Registering, and signing in from a device we do not recognise, requires a code sent to your email address and a code sent to your mobile number, entered together as one step. Signing in with Google, Microsoft or Apple does not substitute for either — it proves the provider knows you, not that you control those two channels. {% endblocktranslate %}

{% blocktranslate %} Approving a return, changing someone's role, changing a payment method, exporting data and granting access all require re-authentication at the moment you do them. Passwords are hashed with Argon2. Every trusted device and active session is listed in your account, and can be ended remotely — which takes effect immediately, including on the mobile app. {% endblocktranslate %}

{% translate "Authorisation" %}

{% blocktranslate %} Permissions are codes, not job titles, and roles are bundles of codes that a customer can compose. Access is scoped by entity, by department and by compliance category at the same time, so a payroll manager sees payroll and not a tax demand. Every routable view declares the permission it requires, and the build fails if one does not. {% endblocktranslate %}

{% translate "Audit trail" %}

{% blocktranslate %} Every state change is recorded with the person who made it, the time, the network address and what changed. The audit table is append-only: the database rejects attempts to update or delete a row, so the record cannot be quietly revised. You can export the full trail for your account at any time. {% endblocktranslate %}

{% translate "Support access" %}

{% blocktranslate %} Our staff cannot browse your data. Support access requires your consent, is time-boxed, is shown to you in the interface while it is active, and is logged. There is no silent impersonation. {% endblocktranslate %}

{% translate "Data residency and the DPDP Act" %}

{% blocktranslate %} Data belonging to Indian customers is stored in an Indian region. Consent records, purpose limitation, and the data-principal rights of access, correction and erasure are product features rather than policy statements. A documented retention schedule applies per class of data. {% endblocktranslate %}

{% blocktranslate %} We act as a processor for the customer data held in your account, on your documented instructions. The data processing addendum sets out those instructions, and the sub-processor list names every third party involved. {% endblocktranslate %}

{% translate "Encryption" %}

{% blocktranslate %} Traffic is encrypted in transit. Storage is encrypted at rest. Tax identifiers, bank details and any credentials held for government portals receive additional field-level encryption. We would rather not hold Aadhaar-adjacent data at all, and store only what a filing genuinely requires. {% endblocktranslate %}

{% translate "Availability and recovery" %}

{% blocktranslate %} Databases are backed up continuously with point-in-time recovery, and restores are exercised rather than assumed. Availability targets, planned maintenance windows and support response times are written down on the service levels page instead of being agreed per customer. {% endblocktranslate %}
