{% load i18n crispy_forms_tags %} {% comment %} The entity form, in a modal loaded on demand. Creates and edits. Loaded by hx-get into #modal-container and shown by the modal hook in app.js. Loading it on demand rather than rendering a hidden dialog into every page keeps the shell small — there will eventually be a lot of these. Where it posts and what it swaps come from the view — `form_action`, `form_target`, `form_swap` — rather than from a `{% if %}` here. Creating prepends a row to the table; editing replaces the row it was opened from. There is no third case, and putting the choice in the view keeps the two callers honest about which one they are. On a validation failure the view returns 422 with only this fragment, so the modal stays open and keeps what the user typed. HTMX is configured to swap 422 responses precisely for this, and app.js retargets them back into #modal-container so the form does not land in the list. {% endcomment %}
