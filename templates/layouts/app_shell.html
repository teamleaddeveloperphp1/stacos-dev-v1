{% load i18n static %} {% comment %} The persistent application shell. This renders ONCE per full page load. Navigation replaces only #main, so the sidebar, header, tenant switcher and notification state never re-render and the application never blinks. That single decision is most of the difference between "a website" and "an app". Which is also why nothing here computes the active nav item. It used to, from `request.resolver_match`, and because the sidebar never re-renders the highlight stayed frozen on whatever page was last loaded from the address bar — correct only after a manual refresh. Each link now declares the URL prefix it owns as `data-nav-match`, and `syncNav()` in assets/js/app.js applies `aria-current="page"` to the longest match on first paint and after every navigation. One rule, in one place: a server-side copy and a client-side copy drifted apart the moment the two used different comparisons, which is exactly what had happened (`url_name` for some links, `namespace` for others, and none at all for two of them). `data-nav-exact` is for Dashboard, whose `/app/` prefix would otherwise match every page in the product. Every link inside .app-shell inherits hx-boost from the wrapper, so it swaps #main, pushes the URL, and morphs rather than replaces. A direct GET to any of those URLs still returns this full page, which is what keeps deep links, the back button and "open in new tab" working. There is deliberately no `hx-push-url` here, and adding one back breaks the app in a way that is easy to misread as cosmetic. It would be inherited by every descendant, so opening a modal, submitting a panel action, clicking "Load more" or typing in the palette would each push its own endpoint into browser history — and refreshing or pressing Back would then land on a bare fragment. It is not needed for navigation either: HTMX already pushes the URL for boosted links and forms on its own. `tests/test_templates.py` guards this. {% endcomment %} {% block title %}{% translate "STACOS" %}{% endblock %} {% comment %} `hx-ext` is on the body, not on .app-shell. HTMX extensions apply to an element and its descendants, and the command palette, modal container and toast stack all live outside the shell — with the extension scoped to the shell their swaps would silently fall back, and `defaultSwapStyle = "morph"` would name a strategy that was not loaded for them. {% endcomment %} {% translate "Skip to main content" %} {# Progress bar for navigations that outlast ~180ms. #}
